Self-managed PostgreSQL 18 on Render is viable for in-Render Bemi access over the private network.

Use the container image/build that includes wal2json. The self-managed superuser can create the replication roles, publications, and logical slots Ardent needs.

Internal Render connection target: `alliance-postgres-18:10000` with database `alliance_test`.

Keep the existing Render Managed Postgres config as the fallback path.

Render public web services expose HTTP(S), not raw public PostgreSQL TCP. Render private services can carry raw PostgreSQL TCP internally only, so Ardent's direct external connector uses the `alliance-ardent-ngrok-tunnel` worker.

Ardent ngrok TCP endpoint: `7.tcp.ngrok.io:25575` forwards to `alliance-postgres-18:10000`.

No secrets belong in this file.

Bemi runs over Render's private network to `alliance-postgres-18:10000`; set `DB_PASSWORD` to the Bemi replication role password and `DESTINATION_DB_PASSWORD` to the app writer password in Render env vars during deployment.
